# 식수 관리 웹 서비스

약 20명 규모의 회사에서 관리자가 당일 식사 불참자만 체크하고, 최종 식사 인원을 식당에 SMS로 전달하는 웹 서비스입니다.

대부분의 직원이 매일 식사에 참여한다는 운영 환경을 반영해 직원용 페이지는 만들지 않습니다. 재직 직원은 기본적으로 모두 식사하는 것으로 간주하며, 관리자가 구두로 전달받은 불참자만 관리자 화면에서 선택합니다.

## MVP 운영 흐름

```text
재직 직원 전원을 기본 '식사'로 간주
        ↓
관리자가 구두로 전달받은 당일 불참자만 체크
        ↓
09:50부터 '최종 확정 및 문자 전송' 가능
        ↓
최종 식사 인원 계산 및 당일 기록 확정
        ↓
식당으로 SMS 전송 후 결과 저장
```

- 식사 상태는 `식사`와 `불참` 두 가지만 사용합니다.
- 오늘 날짜의 식수만 관리합니다.
- 관리자가 아무 작업도 하지 않으면 재직 직원 전원이 식사하는 것으로 계산합니다.
- 집계에는 상태가 `재직`인 직원만 포함합니다.
- 직원별 기본 식사 여부, 입사일 및 퇴사일 기반 자동 처리는 사용하지 않습니다.
- 직원 명단과 재직 상태는 관리자가 직접 관리합니다.
- 최종 확정 후에는 불참자와 식사 인원을 수정할 수 없습니다.
- SMS가 실패하면 확정된 동일 내용으로만 재전송할 수 있습니다.
- 같은 날짜의 중복 확정 및 중복 발송을 방지합니다.

## 휴일 처리

- 토요일과 일요일은 서버에서 자동으로 판별합니다.
- 대한민국 법정공휴일과 대체공휴일은 공공데이터포털의 [한국천문연구원 특일 정보 API](https://www.data.go.kr/dataset/15012690/openapi.do)를 이용해 동기화합니다.
- 공휴일 정보는 DB에 저장하여 외부 API 장애가 발생해도 마지막 동기화 결과를 사용할 수 있게 합니다.
- 주말과 공휴일에는 식수 확정 및 SMS 발송 기능을 비활성화합니다.

## 서비스 구조

MVP는 하나의 웹 애플리케이션으로 구성합니다.

```text
웹 서비스
└── /admin                  관리자 화면

공통 구성
├── 웹 서버/API
├── 직원·식수·휴일·SMS DB
├── 공휴일 동기화 작업
└── SMS 서비스 연동
```

직원용 페이지와 직원 인증 기능은 MVP 범위에서 제외합니다.

## 주요 기능

### 관리자 인증

- 고유 로그인 아이디와 비밀번호로 로그인
- 표시 이름은 로그인 아이디와 분리
- 비밀번호는 Argon2id 해시로 저장
- 서버에 저장된 불투명 세션과 HttpOnly 쿠키 사용
- 관리자 공개 회원가입은 제공하지 않음
- 현재 비밀번호 확인 후 로그인 아이디와 비밀번호 변경
- 계정 정보 변경 시 다른 브라우저의 기존 세션 종료

### 직원 관리

- 직원 추가 및 정보 수정
- 직원 추가 시 환경 설정에 정의된 부서 목록에서 선택
- 연락처 입력 시 11자리 제한 및 `010-0000-0000` 자동 서식 적용
- 직원 상태를 `재직`, `휴직`, `퇴사`로 변경
- 직원 삭제 시 목록과 집계에서는 숨기되 데이터를 유지하여 과거 기록 보존

### 당일 식수 관리

- 재직 직원 명단 표시
- 불참자 체크 및 해제
- 전체 재직자, 불참자, 최종 식사 인원 실시간 표시
- 불참자 이름 목록 확인
- 오전 9시 50분부터 최종 확정 가능
- 확정 전 최종 인원과 불참자 확인
- 확정 이후 변경 차단

### SMS 관리

- 최종 확정과 동시에 식당으로 SMS 발송
- 발송 성공 및 실패 결과 저장
- 실패한 문자를 확정된 내용 그대로 수동 재전송
- 날짜별 중복 확정 및 중복 발송 방지
- 발송 이력 조회

## SMS 예시

최종 문구는 SMS 업체 선정과 함께 확정합니다.

```text
[회사명] 2026년 9월 8일 식사 인원은 17명입니다.
```

불참자 이름은 문자에 포함하지 않고 최종 식사 인원만 전송하는 것을 기본으로 합니다.

## 권장 기술 구성

- 프로토타입: FastAPI, Jinja2, SQLAlchemy
- 프로토타입 DB: SQLite
- 운영 DB: PostgreSQL
- SMS: 국내 SMS 발송 업체 API
- 공휴일: 한국천문연구원 특일 정보 API
- 배포: Docker 기반 서버 또는 클라우드 서버
- 기준 시간대: `Asia/Seoul`

초기 규모에서는 마이크로서비스를 사용하지 않고 웹 서버, DB, 공휴일 동기화 작업을 하나의 프로젝트에서 운영합니다.

## 프로토타입 실행

Python 3.11 이상이 필요합니다.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
uvicorn app.main:app --reload
```

브라우저에서 `http://127.0.0.1:8000`에 접속합니다. 환경 변수를 별도로 설정하지 않은 개발 환경의 초기 로그인 정보는 다음과 같습니다.

```text
아이디: admin
비밀번호: LunchCall123!
```

초기 비밀번호는 로컬 프로토타입 전용입니다. 외부에 배포하기 전 `ADMIN_PASSWORD`를 안전한 값으로 반드시 변경해야 합니다.

현재 `SMS_MODE=mock`에서는 실제 문자를 발송하지 않고 성공 이력만 DB에 기록합니다. 실제 SMS 업체가 결정되면 공통 발송 서비스의 공급자 어댑터를 교체합니다.

개발 환경의 목업 모드에서는 확정 후 `목업 확정 초기화`를 눌러 오늘의 확정 상태와 모의 SMS 이력을 제거할 수 있습니다. 기존 불참 선택은 유지되며, 운영 환경과 실제 SMS 모드에서는 사용할 수 없습니다.

공휴일 동기화를 사용하려면 공공데이터포털에서 한국천문연구원 특일 정보 API 활용 신청 후 `HOLIDAY_API_KEY`를 설정합니다. 키가 없어도 주말 판별과 나머지 프로토타입 기능은 동작합니다.

정책상 오전 9시 50분 전에는 확정할 수 없습니다. UI 검증이 꼭 필요한 경우에만 로컬 환경에서 `PROTOTYPE_ALLOW_EARLY_CONFIRM=true`로 설정할 수 있습니다. 운영 환경에서는 사용하지 않습니다.

테스트는 다음 명령으로 실행합니다.

```powershell
pytest -q
```

## 개발 단계

### 1단계: 수동 확정 MVP

- 관리자 로그인
- 직원 및 재직 상태 관리
- 당일 불참자 체크
- 최종 식사 인원 계산
- 관리자 최종 확정
- SMS 발송 및 이력 조회
- 공휴일 자동 동기화
- 중복 확정 및 중복 발송 방지

### 2단계: 운영 안정화

- SMS 실패 재시도 정책 보강
- 관리자 알림
- 감사 로그
- DB 자동 백업
- 모니터링

### 3단계: 자동 발송

서비스가 안정화되면 관리자의 수동 확정 대신 오전 9시 50분에 스케줄러가 같은 확정·발송 로직을 실행하도록 전환합니다. 수동 버튼과 스케줄러가 동일한 공통 서비스를 호출하도록 처음부터 설계합니다.
